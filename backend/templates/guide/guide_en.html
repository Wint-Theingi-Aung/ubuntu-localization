This tool helps you localize Ubuntu software into indigenous languages. It uses Google Gemini AI to translate untranslated strings in .po files — the standard format for Linux software translations.

With this tool you can:

  • Upload .po or .pot files from Ubuntu or any GNOME project
  • See which strings are already translated and which still need work
  • Get AI-powered translations using Gemini 2.5 Flash
  • Manually edit translations in a side-by-side view
  • Run automatic quality checks on every AI translation
  • Export the completed .po file for download

Everything happens on a single page — the Translate page.

Supported Languages

Language Code Script Word Order
Burmese my Myanmar Unicode SOV (Subject + Object + Verb)
Shan shn Shan Unicode SVO (Subject + Verb + Object)
Mon mnw Mon Unicode SVO (Subject + Verb + Object)
S'gaw Karen ksw Karen Unicode SVO (Subject + Verb + Object)

Requirements

  • A .po or .pot file to translate
  • Google Gemini API key (configured in .env on the server)
  • No installation needed — works directly in your browser

Where to Get .po Files

You can get .po files from these sources:

  • Launchpad Translations — translations.launchpad.net/ubuntu
    Select your language → choose a package → click Download translation → select .po format
  • Your own project — use xgettext -o messages.pot src/*.py to generate a .pot template
  • Ubuntu package source — many packages include .po files under a po/ folder in their source tree

Upload Steps

  1. Go to the Translate page
  2. Drag your .po or .pot file into the upload area (or click to browse)
  3. If the language is not auto-detected, select the target language from the dropdown
  4. Click Upload & Parse

The tool will then:

  • Read the file and extract all entries (msgid, msgstr, context comments)
  • Auto-detect the language from file metadata or filename
  • Show a summary: total strings, translated count, and untranslated count
  • Prepare the translation workspace so you can start immediately

Supported File Types

  • .po files — standard GNU gettext portable object files
  • .pot files — gettext template files (no translations yet)
  • Maximum file size: 50 MB
  • Must be UTF-8 encoded

{{ guide_headings.how_translation_works }}

This tool uses Google Gemini 2.5 Flash, a state-of-the-art large language model, to translate English strings into your target language. Gemini understands the context of Ubuntu and Linux software, producing translations that are natural and technically accurate.

Step-by-Step Process

  1. Batch preparation: Untranslated strings are grouped into batches of 15 — the optimal size for quality and speed.
  2. AI translation: Each batch is sent to Gemini with language-specific instructions. The AI is told to:
    • Preserve all placeholders: %s, %d, {0}, $1
    • Never translate technical terms: Kernel, GNOME, sudo, apt, GRUB, X11, Wayland
    • Keep brand names unchanged: Ubuntu, Canonical, Debian, Firefox
    • Maintain exact whitespace and newline patterns
    • Use formal, professional tone appropriate for software interfaces
  3. Quality checks: Each translated string is automatically validated:
    • ✅ Placeholder integrity: Are all %s, %d markers present?
    • ✅ Newline count: Does the line-break count match?
    • ✅ Non-empty: Is the translation filled in?
    • ✅ Length ratio: Is the length reasonable compared to the source?
  4. Display results: Each translated string appears with a ✅ (passed) or ⚠️ (flagged) icon. Flagged translations can be manually reviewed and corrected.

Clicking the Translate Button

After uploading a file, you'll see a "🤖 Translate Page" button. Click it to translate all untranslated strings on the current page. If there are many strings, click it for each page. An auto-translate mode also triggers translation immediately after upload.

AI translations are good, but some may need adjustment. The tool provides a side-by-side editor where you can type your own translation or refine the AI's output.

Editor Layout

  • Left side: Original English text (read-only)
  • Right side: Text box for typing or editing the translation
  • Context line: If the original file has context comments, they appear below

Auto-Save

Edits are saved automatically. When you click outside a text box (or press Tab), a "✓ Saved" indicator appears. No need to click a save button. Even if you close your browser, your translations are safely stored — just return to your session URL.

Reviewing AI Translations

After AI translation, each string shows quality check results:

  • ✅ Passed — all checks passed. Ready to use.
  • ⚠️ Flagged — one or more checks failed. Review and correct if needed.

Click into the text box to fix flagged translations. Check tags next to each string show exactly which checks passed and which failed.

Pagination

If your file has many untranslated strings, they are split into pages of 10. Use the ← Previous and Next → buttons at the bottom of the translation grid to navigate between pages. Translations from earlier pages are preserved and included when you export.

{{ guide_headings.exporting_work }}

Once some or all strings are translated, you can export them as a .po file. The Export section appears at the bottom of the Translate page once you have saved translations.

What You Get

  • A .po file combining previously existing translations with your new ones
  • Filename format: translated_<language-code>_<source-name>_<YYYYMMDD_HHMM>.po

Export Preview

The export preview shows:

  • Total string count in the file
  • Previously translated strings (from the original file)
  • Your newly added translations (+N)
  • QA passed count
  • Completion percentage — before and after your work
  • Output filename

How to Export

Click the "📥 Export .po File" button at the bottom of the Export section. A download link will appear — click it to save the file to your computer.

What to Do with the Exported File

  • Submit to Launchpad: Go to translations.launchpad.net and upload your .po file
  • Test in Ubuntu: Replace the .po file inside a package and rebuild

General Tips

  • Start with small files. If you're new, try files with 20–30 untranslated strings first. This helps you get familiar with the tool before tackling larger files.
  • Translate by priority. The tool classifies strings by visibility: P1 (menus, buttons, dialogs) are seen by every user — start there. P2–P3 (help text, descriptions) can come later.
  • Review flagged strings. AI is good but not perfect. A ⚠️ flagged translation may have a missing placeholder or be too long — click in and check it.
  • Don't modify placeholders. %s, %d, {0} and similar codes are replaced by the program at runtime. Changing or removing them will break the software.
  • Save as you go. You don't need to finish everything in one sitting. Export what you have, and return to your session later to continue.
  • Bookmark your session. The page URL with ?session_id=... lets you return to your workspace. Sessions are stored on the server, so closing your browser won't lose them.

Language-Specific Tips

Burmese (မြန်မာ)

  • Always use Unicode — never use Zawgyi encoding
  • Use formal, respectful language — software interfaces should be polite
  • Burmese is SOV: verbs come at the end — placeholder positions stay the same but surrounding words may need reordering
  • If no established translation exists, keep technical terms in English

Shan (တႆး)

  • Preserve all tone markers — they change meaning
  • Shan Unicode is relatively new — test that your output displays correctly in Ubuntu
  • Shan follows SVO word order like English, so word placement is often similar

Mon (မန်)

  • Verb-final structure is common — be careful not to copy English word order
  • Mon script shares some characters with Burmese — distinguish carefully
  • Review AI translations of complex sentences extra carefully — Mon grammar differs significantly from English

S'gaw Karen (ကညီ)

  • Karen uses SVO like English, so AI translations tend to be structurally reliable
  • Watch tone markers and diacritics — they can get lost during copy-paste
  • For Ubuntu terms without established Karen equivalents, use descriptive phrases rather than forcing single-word translations

Common Mistakes

  • Accidentally deleting placeholders. If the source has %s or %d, make sure they appear identically in your translation.
  • Missing or extra newlines. If the source starts or ends with \n, your translation must too. The QA check catches this, but it's better to be aware upfront.
  • Translating proper names. Ubuntu, GNOME, Firefox, Linux, and package names must stay unchanged.
  • Skipping QA review. Always check the quality tags below each AI-translated string. Flagged text may have a real issue.
