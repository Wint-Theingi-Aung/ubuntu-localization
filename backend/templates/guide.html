📖 What This Tool Does

This tool helps you translate Ubuntu software into indigenous languages. It uses Google Gemini AI to translate untranslated strings in .po files — the standard format for software translations in Linux.

Here is what you can do with it:

  • Upload a .po or .pot file from Ubuntu or any GNOME project
  • See which strings are already translated and which still need work
  • Get AI-generated translations powered by Gemini 2.5 Flash
  • Edit translations manually in a side-by-side view
  • Each AI translation goes through automatic quality checks
  • Export the finished .po file and commit it to Git

Everything happens on one page: the Translate page.

Supported Languages

Language Code Script Word Order
Burmese my Myanmar Unicode SOV
Shan shn Shan Unicode SVO
Mon mnw Mon Unicode SVO
S'gaw Karen ksw Karen Unicode SVO

What You Need

  • A .po or .pot file to translate
  • A Google Gemini API key (set in the .env file on the server)
  • No installation required — it runs in your browser

📤 Uploading a .po File

Where to Get .po Files

You can get .po files from several places:

  • Launchpad Translations — translations.launchpad.net/ubuntu
    Select your language → pick a package → click Download translation → choose .po format
  • Your own project — generate a .pot template with xgettext -o messages.pot src/*.py
  • Ubuntu package source — many packages ship .po files inside their source tree under a po/ folder

How to Upload

  1. Go to the Translate page
  2. Drag your .po or .pot file onto the upload area — or click it to browse
  3. Select the target language from the dropdown if the file does not auto-detect one
  4. Click Upload & Parse

The tool will:

  • Parse the file and extract every entry (msgid, msgstr, context comments)
  • Detect the language from the file metadata or filename
  • Show you a summary: total strings, how many are already translated, and how many are missing
  • Automatically display the translation workspace so you can start right away

Supported File Types

  • .po files — standard GNU gettext portable object files
  • .pot files — gettext template files (no translations yet)
  • Maximum file size: 50 MB
  • Must be UTF-8 encoded

🤖 How Translation Works

The tool uses Google Gemini 2.5 Flash — a large language model — to translate strings from English into your target language. It is not a simple word-for-word translator. Gemini understands the context of Ubuntu and Linux software, so it produces natural, technically accurate translations.

Step by Step

  1. Batch preparation: Untranslated strings are grouped into batches of 15. This is the optimal size for quality and speed.
  2. AI translation: Each batch is sent to Gemini with instructions specific to your language. The AI is told to:
    • Keep all placeholders exactly as-is: %s, %d, {0}, $1
    • Never translate technical terms: Kernel, GNOME, sudo, apt, GRUB, X11, Wayland
    • Preserve brand names: Ubuntu, Canonical, Debian, Firefox
    • Match the original whitespace and newline count
    • Use formal register appropriate for software interfaces
  3. Quality checks: After translation, each string goes through automatic verification:
    • ✅ Placeholder check: Are all %s, %d placeholders intact?
    • ✅ Newline check: Does the number of line breaks match?
    • ✅ Empty check: Is the translation field populated?
    • ✅ Length check: Is the length within a reasonable range of the original?
  4. Results display: Each translated string appears with a ✅ (passed) or ⚠️ (flagged) icon. You can review flagged translations and edit them manually.

Clicking the Translate Button

On the Translate page, after uploading a file, you will see an "🤖 Translate Page" button. Clicking it translates all untranslated strings on the current page. If you have many strings, click it for each page. There is also an auto-translate mode that starts immediately after upload.

✏️ Editing Translations

AI translations are good, but sometimes you will want to adjust them. The tool gives you a side-by-side editor where you can type your own translations or fix the AI output.

The Editing Layout

  • Left side: The original English string (read-only)
  • Right side: A text box where you can type or edit the translation
  • Context line: If the original file included context comments, they appear below

Auto-Save

Changes save automatically. When you click away from a text box (or press Tab), a "✓ Saved" indicator appears. You do not need to click a save button. Your translations are stored safely even if you close the browser — just come back to the same session URL.

Reviewing AI Translations

After AI translation, each string gets a quality check result:

  • ✅ Passed — the AI output passed all checks. Ready to use.
  • ⚠️ Flagged — one or more checks failed. Review and edit if needed.

Clicking into the text box lets you fix flagged translations. The check results are shown as small tags next to each entry — they tell you exactly what passed and what did not.

Pagination

If your file has many untranslated strings, they are split across pages of 10. Use the ← Previous and Next → buttons at the bottom of the translation grid to move between pages. Translations from earlier pages are saved and will be included in the export.

📦 Exporting Your Work

When you have translated some or all of the strings, you can export them back to a .po file. The export section appears at the bottom of the Translate page once translations are saved.

What Export Produces

  • A .po file with all translations merged in — both existing translations from the original file and your new ones
  • A manifest file (.json) that records what was exported, when, and how many strings were translated
  • The filename follows the pattern: translated_<language-code>_<source-name>_<YYYYMMDD_HHMM>.po

Before You Export

The export preview shows you:

  • Total entries in the file
  • Previously translated strings (from the original file)
  • New translations you added (+N)
  • QA pass count
  • Completion percentage — before and after your work
  • The output filename
  • Current Git branch and whether it is clean

Two Export Options

  1. 📦 Export & Commit — writes the .po file, stages it in Git, and creates a commit with a descriptive message. Recommended when you are ready to share your work.
  2. 📥 Export Only — writes the .po file and manifest but does not commit. Use this when you want to review the file further or handle Git manually.

After export, a Download .po file link appears — click it to save the file locally.

What to Do With the Exported File

  • Upload to Launchpad: Go to translations.launchpad.net and submit your .po file
  • Push to GitHub: git push origin ai-enhanced
  • Open a Pull Request: Get your translations reviewed
  • Test in Ubuntu: Replace the .po in the package and rebuild

💡 Tips for Best Results

General Tips

  • Start with small files. If you are new, try a file with 20–30 untranslated strings first. This lets you get familiar with the tool before tackling larger files.
  • Translate in priority order. The tool classifies strings by visibility: P1 (menus, buttons, dialogs) are seen by every user. Start there. P2–P3 strings (help text, descriptions) can wait.
  • Review flagged translations. The AI is good, but it is not perfect. A ⚠️ flagged translation might have a missing placeholder or be too long. Click in and check.
  • Keep placeholders unchanged. %s, %d, {0}, and similar codes are replaced by the program at runtime. If you change or delete them, the software will crash or show errors.
  • Save partial work. You do not need to translate everything in one sitting. Export what you have done (use Export Only) and resume later with the same session.
  • Use the same session. Bookmark the page URL with ?session_id=... to return to your work. Sessions are stored on the server and persist across browser restarts.

Language-Specific Tips

Burmese (မြန်မာဘာသာ)

  • Always use Unicode, never Zawgyi encoding
  • Use formal register — software interfaces should sound polite
  • Burmese has SOV word order, so verbs come at the end — placeholder positions can stay the same, but surrounding words may need reordering
  • Keep technical terms in English unless there is a well-established translation (e.g., "ကွန်ပျူတာ" for "computer")

Shan (ၽႃႇသႃႇတႆး)

  • Preserve all tone marks — they change meaning
  • Shan Unicode is relatively new; test that your output renders correctly in Ubuntu
  • Shan follows SVO word order, similar to English — word order usually maps well

Mon (ဘာသာမန်)

  • Mon is verb-final in many constructions — be careful not to mirror English word order
  • Mon script shares characters with Burmese; distinguish carefully
  • Review AI translations especially for complex sentences — Mon grammar differs significantly from English

S'gaw Karen (ကညီကျိာ်)

  • Karen uses SVO order like English, so AI translations tend to be structurally reliable
  • Watch for tone markers and diacritics — these are easy to lose during copy-paste
  • Some Ubuntu-specific terms may not have established Karen translations — use a descriptive phrase instead of a forced one-word equivalent

Common Pitfalls

  • Accidentally deleting a placeholder. If you see %s or %d in the original string, copy it exactly into the translation.
  • Adding or removing newlines. If the original string starts or ends with \n, your translation should too. The QA checks catch this, but it is good to be aware.
  • Translating proper names. Ubuntu, GNOME, Firefox, Linux, and package names should stay as-is.
  • Skipping the QA review. Always glance at the check tags below each AI-translated string. A flagged string might have a real issue.
